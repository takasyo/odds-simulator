# オッズ配分 / ODDS SIM

予算と各買い目のオッズから、100円単位の購入額を配分し、想定払戻金の差を抑える静的Webアプリです。入力すると結果が即時に更新されます。ライト/ダークテーマは端末設定に追従し、ヘッダーのボタンで切り替えられます。テーマと入力内容はブラウザー内に保存され、サーバーへ送信されません。フォントの読み込みにはGoogle Fontsを使用し、通信できない場合は端末の日本語フォントを使います。

## 開発・検証

Node.js 24以降を使用します。

```sh
npm ci
npm run dev
```

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

`npm run preview`で本番ビルドを確認できます。ブラウザーテストはビルド済みの画面を`/odds_sim/`配下で起動し、PCとモバイルの両方を検証します。

## GitHub Pages

1. このリポジトリをGitHubに配置します。
2. Settings → Pages → Build and deployment → Sourceを **GitHub Actions** に設定します。
3. `main`へpushするか、Actionsの **Test and Deploy Pages** を手動実行します。
4. 完了後、Pages設定またはActionsの`github-pages`環境に表示されたURLを開きます。

ワークフローはテスト・ビルド・ブラウザーテストに成功した場合だけ`dist`を公開します。プルリクエストでは検証だけ行います。アセットURLは相対パスなので、プロジェクト用Pagesのサブパスでも動作します。既定ブランチを変更する場合はワークフローの`branches`も変更してください。

## 計算仕様

各買い目の理論購入額は次のとおりです。

```text
理論購入額 = 予算 × (1 / その買い目のオッズ) / Σ(1 / 各買い目のオッズ)
購入額 = floor(理論購入額 / 100) × 100
想定払戻金 = 購入額 × オッズ
収支 = 想定払戻金 - 実際の購入合計
```

計算は「基準配分」と「残額の最適化」の2段階です。金額は100円単位で扱い、オッズは小数第2位までの整数（例：12.9倍を1,290）に変換して計算します。

#### 1. 逆オッズによる基準配分

各買い目に対して、オッズの逆数に比例した理論購入額を求めます。オッズが低い買い目ほど購入額が大きくなります。

```text
逆オッズ比の重み w[i] = 1 / odds[i]
理論購入額[i] = 配分対象の予算 × w[i] / Σw
基準購入額[i] = floor(理論購入額[i] / 100) × 100
```

基準購入額は買い目ごとに100円未満を切り捨てます。切り捨てで生じた残額は、この時点ではまだ配分されません。

#### 2. 100円単位の残額を最適化

基準購入額より少なくならないことを条件に、残額から追加する100円単位を各買い目へ配ります。比較するのは、購入額が0円より大きい買い目の想定払戻金の「最高額 − 最低額」です。目標はこの差を小さくすることであり、利益や的中率を最大にする計算ではありません。

```text
想定払戻金[i] = 購入額[i] × odds[i]
払戻差 = max(購入する買い目の想定払戻金) - min(同払戻金)
```

残額をすべて使う配分だけでなく、100円単位で一部を使う配分も候補にします。残額を追加するほど払戻差が必ず小さくなるとは限らないためです。各候補について可能な配分の払戻差を比較し、最小の差を選びます。最小差が同じ候補が複数ある場合は、追加額が大きく、予算をより多く使う候補を優先します。追加しても基準配分より差が小さくならない場合は、基準配分のままです。

計算では、候補となる払戻額をもとに「この差以内に全買い目を収められるか」を判定します。購入額は100円単位の整数なので、各買い目の追加単位の範囲と合計が予算内に収まるかを確認し、最小の払戻差を探索します。0円を許可する場合は、購入額0円の買い目を候補から外せる一方、購入点数が2点以上になる条件も同時に満たす必要があります。

逆オッズ比の基準配分は整数演算（BigInt）で求めます。これにより、小数の丸め誤差で100円単位の購入額がずれることを防ぎます。払戻金は入力オッズに基づく概算です。

### 0円を許可しない場合

すべての買い目に最低100円を確保します。理論額が100円未満になる買い目を100円に固定し、残予算を残りの買い目に逆オッズ比で再配分します。新たに100円未満になる買い目がなくなるまで繰り返し、最後に100円未満を切り捨てます。購入予算が`買い目数 × 100円`未満の場合はエラーです。

最低額の補正が入る買い目では払戻金が大きくなる場合があります。その補正後の購入額も、最適化で減らすことはありません。

### 0円を許可する場合（初期設定）

基準配分を100円単位で切り捨て、100円未満の買い目は購入額0円になります。払戻差を小さくするため、基準配分で0円だった買い目に追加配分する場合があります。購入する買い目は最低2点必要で、満たせない場合はエラーになります。

サマリーの最低・最高払戻金、差、最低収支は購入額が正の買い目だけを対象にします。購入しない買い目の的中時は払戻金0円・購入合計分の損失になることを別途表示します。

### 例

予算欄に`100`を入力すると10,000円です。

| オッズ | 基準購入額 | 基準払戻金 | 最適化後の購入額 | 最適化後の払戻金 |
|---:|---:|---:|---:|---:|
| 12.9 | 4,100円 | 52,890円 | 4,200円 | 54,180円 |
| 11.8 | 4,500円 | 53,100円 | 4,500円 | 53,100円 |
| 42.2 | 1,200円 | 50,640円 | 1,300円 | 54,860円 |

基準配分では合計9,800円で、残額は200円です。最適化後はその200円を1・3番目の買い目に追加し、購入合計10,000円、残予算0円になります。払戻差は基準配分の2,460円（52,890円 − 50,640円）から1,760円（54,860円 − 53,100円）に縮小します。

オッズ10・20・50の場合も基準配分5,800円・2,900円・1,100円から、5,800円・3,000円・1,200円へ再配分します。想定払戻金は58,000円・60,000円・60,000円、払戻差は2,000円です。

一方、オッズ2・2、予算900円では、基準配分の400円・400円で払戻差がすでに0円です。残る100円を追加すると差が広がるため、購入合計800円・残予算100円のままにします。

### 入力範囲と前提

- 予算欄：1〜10,000の整数（100円単位）。入力値を100倍した金額が予算となり、100〜1,000,000円の範囲です。小数・指数表記は使用できません。上下キーでは100円ずつ増減します。
- 買い目：1〜30点。0円を許可する場合は2点以上。
- 追加した買い目のオッズ初期値は10倍です。
- オッズ：1〜9,999.99倍、小数第2位まで。
- 予算・オッズ欄をクリックまたはタップすると、カーソルが数字の末尾へ移動します。買い目名の入力欄は対象外です。
- 各買い目を独立した的中ケースとして表示し、同時的中・税金・特殊な払戻ルールは扱いません。
- 表示値は入力時点のオッズに基づく概算です。的中・利益を保証しません。
